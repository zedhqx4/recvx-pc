## Resumen ejecutivo

La build PC no ejecuta un emulador de GS ni consume cadenas GIF/DMA/VIF. Conserva **semántica y datos de compatibilidad PS2** en las fuentes compartidas, pero la ruta PC traduce primitivos/estado a llamadas de renderer nativo. El propio encabezado de `pc_libgraph.c:1-5` declara que el renderer no interpreta GIF, no emula registros GS, no mantiene VRAM GS y no traduce cadenas DMA.

Hay tres cosas distintas que no deben mezclarse:

1. **Hardware PS2 real (GS/GIF/VIF/DMA/EE):** ramas `#ifndef TARGET_PC` y código de plataforma PS2. No se ejecutan en la build PC.
2. **Compatibilidad de API/datos PS2:** nombres `sceGs*`, registros codificados, estructuras `u_long128`, tags y funciones stub. Algunos puntos siguen enlazados por el código compartido, pero sus stubs no simulan el hardware.
3. **Renderer PC nativo:** recibe primitivos/estado convertidos a estructuras C y llama a OpenGL. Este sí es vivo y no se puede retirar por tener nombres GS alrededor.

### GS: veredicto práctico

- `Ps2AddPrim*`, la carga nativa TIM2/CLUT, el estado ALPHA y el intercambio/presentación son **NO TOCAR** en una retirada mecánica.
- Los registros y macros GS son **candidatos a encapsular/reemplazar**, pero no a borrar todavía: parte de ellos codifica el contrato de entrada que el código compartido sigue construyendo.
- La VRAM GS física no está emulada en el renderer PC. Existe una **VRAM lógica parcial** para CLUT y bookkeeping, y una ruta separada de render targets; no son equivalentes a una memoria GS completa.

## 4. Otros módulos que simulan hardware

- **IOP:** `pc_iop.c:1-7` describe que los módulos IOP se sustituyen por servicios PC asociados a IDs RPC; RAM emulada en `:19-44`, registro/arranque de servicios en `:50-61`, carga/copia en `:100-101,192-217`. **VIVA** como capa de servicios y memoria; no es un IOP MIPS completo. No tocar sin inventariar los RPC que usan audio, CD/DVD y sistema.
- **Audio/SPU:** existen `pc_audio.c`, `pc_iop_tsnddrv.c`, `pc_spu_gauss.h` y servicios IOP. No se hizo auditoría de todos los comandos SPU/ADPCM; **DUDOSA**, fuera del alcance principal de G3. No borrar por analogía con GS.
- **CD/DVD, MPEG y movies:** módulos PC separados `pc_cdvd.c`, `pc_mpeg.c`, `pc_movie.c`; son reemplazos de servicios/formatos PS2. **VIVOS** por su rol de plataforma, pero G3 no verificó cada llamada.
- **Timers/RTC:** headers de sistema PS2 existen, pero no se verificó un emulador de timer de hardware en la ruta PC. **DUDOSA**; auditar aparte si se quiere retirar esa capa.

## Grafo de dependencias (PC)

```text
CNK / dibujo de juego
    -> estructuras compartidas (NJS / VU1_PRIM_BUF / datos de vértice)
    -> Ps2AddPrim* (traducción de primitivo y estado)
    -> pcRendererDraw* / pcRendererSetGsAlpha / depth / scissor
    -> OpenGL renderer + framebuffer
    -> pcVideoPresent

TIM2 + PSM + paletas
    -> Ps2TexLoad / rutas de carga de textura
    -> pcNativeTextureLoad + pcTextureUploadVramClut
    -> caché de texturas GL
    -> pcRendererBindTexture

StoreRenderTex
    -> sceGsExecStoreImage (shim PC, NO GS real)
    -> pcTextureStoreScreenRect (GPU copy) o pcRendererReadScreenRect (fallback CPU)
    -> payload TIM2 / render-target cache

Código compartido -> sceGs*/sceDma*/FlushCache
    -> pc_libgraph / pc_kernel shims
        -> no-op para operaciones de hardware
        -> flush/present/captura cuando el shim tiene semántica PC

Servicios de juego -> RPC IDs -> pcIopRegisterService / pcIopRam
    -> servicios PC (audio, CD/DVD, etc.)
```

## Orden propuesto de retirada (menor a mayor riesgo)

1. **Inventariar y retirar headers EE vacíos/residuales**, solo después de confirmar que no se incluyen transitivamente. Archivos candidatos: `pc/include/eetypes.h`, `eeregs.h`, `libdma.h`, `sif.h` (son wrappers pequeños). Prueba: búsqueda global de includes/símbolos y build PC GCC/MSVC. Riesgo: include indirecto o tipo requerido por un header compartido.
2. **Eliminar stubs estrictamente inertes que ya no tengan llamadores PC**, empezando por `sceVpu0Reset`, `loadImage`, `SyncPath`, `D2_SyncTag`, `sceDmaSend/Sync`. Antes, grep de cada símbolo en TODO `src/`, `pc/` e `include/`; no basta con buscar solo dentro de `pc/src`. Prueba: link completo PC y harness de símbolos. Riesgo: referencia desde código compartido/objeto no inspeccionado.
3. **Aislar macros/tipos de GIF usados solo para construir paquetes PS2**. Mantener los bits de primitivo que alimentan `Ps2AddPrim*`; reemplazar primero el contrato de entrada por un enum/struct PC y comparar todos los draws. Prueba: harness de conversión de primitivos y logs de escena, transparencias y UI. Riesgo: diferencias de topología, ST/RGBAQ/XYZ, flags de fog/blend.
4. **Reescribir las funciones compartidas de transferencia de textura** para que la ruta PC no construya tags GS. Mantener `Ps2TexLoad`, TIM2, PSM y CLUT hasta que la nueva API tenga equivalencia. Prueba: harness de decode/hash por formatos y logs de habitaciones con texturas indexadas/CLUT; comparar StoreRenderTex con `rtt_gpu_copy=0/1`. Riesgo: swizzle, PSMT4/8, paletas, render targets y sincronización de captura.
5. **Retirar ramas PS2 de DMA/VIF y microcódigo** una vez que la compilación PS2 deje de ser objetivo de este repo. Las ramas ya excluidas en PC son candidatas claras, pero solo si se acepta perder build PS2. Prueba: GCC/MSVC PC y búsqueda de referencias; no aplica harness visual para código nunca ejecutado en PC. Riesgo: compilar otra plataforma/SDK.
6. **Reemplazar el estado GS residual (ALPHA, TEST, FRAME/ZBUF, TEX0/TEX1) por estado de renderer explícito**. Mantener la ruta vieja conmutada hasta equivalencia. Prueba: logs/capturas de escenas opacas, transparentes, efectos, fog, z-buffer, UI y render-to-texture. Riesgo: estados globales diferidos, orden de flush y diferencias de blend/depth.
7. **Retirar la capa de tipos EE/PS2 compartidos** solo después de desacoplar todas las estructuras ABI del juego. Prueba: compilación completa y harness de layouts/serialización. Riesgo: offsets binarios, alineación, código de terceros CRI y datos de recursos.

## Preguntas

1. ¿El objetivo final excluye definitivamente la compilación/ejecución PS2? Si se conserva como referencia, no se deben borrar las ramas de DMA/VIF aunque no compilen para PC.
2. ¿`vu1ScessorBuf` es el nombre literal de un símbolo o una errata? Se encontró `VU1_PRIM_BUF` en `types.h:1045-1060`, pero no se confirmó el primero.
3. ¿Se quiere retirar toda la ABI `sceGs*` de los headers compartidos o solo eliminar la emulación física? La segunda opción es compatible con el estado actual; la primera exige migrar varios productores.
4. La sincronización vertical de `pc_kernel.c:905-933` y la semántica de los timers no se validaron contra logs del juego. Se dejan DUDOSAS hasta probar frame pacing y callbacks.
5. No se hizo una búsqueda exhaustiva de cada símbolo `sceGs*`/macro en todos los headers y fuentes generadas CRI. Por eso no se declara MUERTA ninguna función compartida basándose solo en que su cuerpo sea no-op. Antes de retirar cada stub hay que ejecutar, para cada nombre, `git grep -n -w 'NOMBRE' -- src pc include` y revisar todas las coincidencias, incluidas llamadas indirectas.
6. Los rangos de la tabla son estimaciones por bloques identificados, no una clasificación automática línea a línea. Un conteo exacto de VIVAS/MUERTAS requiere preprocesar con el mismo compilador/defines de la build PC y separar funciones compartidas. No se inventa una cifra exacta donde el árbol no permite sostenerla.
