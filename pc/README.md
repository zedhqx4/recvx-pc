# PC port internals

Goal: build Resident Evil Code: Veronica X as a native 32-bit Windows program from the decompiled
sources, replacing the PS2 platform layer (`src/ps2/veronica/prog/ps2_*.c`, CRI middleware, VU
microcode) with a PC one.

## Approach

- **32-bit x86 first.** Asset loaders patch file offsets into pointer fields in place
  (`binfunc.c`, `door.c`, ...), so pointers must stay 4 bytes.
- **`TARGET_PC` switch.** Every change to upstream sources keeps the original code for the PS2
  build:

  ```c
  #ifdef TARGET_PC
  /* C replacement */
  #else
  /* original MWCC/PS2 code */
  #endif
  ```

- **Sony SDK stand-ins** live in `pc/include` (`sce_pc.h` and one stub per SDK header). They only
  declare what the game needs; nothing from the real SDK is required.
- Dreamcast Katana/Ninja headers come from the `include/recvx-decomp-katana` submodule (copied to
  `build_pc/katana_inc` without its libc headers).

## Status

All steps are done: game logic compiles with MSVC x86, the platform layer boots into gameplay,
and rendering, movies, music, sound effects and saves work. See the main [README](../README.md)
for the feature list and known gaps.

VU0 assembly inside game logic was translated by hand (see the `pc/tools/port_*.py` scripts,
which document what each block computes): facial animation (`face_bh.c`), morphing, UV
scrolling and skinning (`njplus.c`), water surface (`objitm.c`) and the LZ decompressor
(`expand.c`).

## Platform layer (`pc/src`)

| File | Replaces |
|---|---|
| `gs/` | Graphics Synthesizer on OpenGL 3.3: GIF/DMA parsing, GS memory, render targets, CLUT buffer, texture cache, PCSX2-format HD texture replacement (`gs_replace.c`) |
| `vu/` | VU0 microcode translated to C |
| `pc_kernel.c` | EE kernel: threads (as fibers, same priority rules), semaphores, alarms, VBLANK interrupts |
| `pc_cdvd.c` | libcdvd: reads sectors from the extracted data folder (`files.idx`) or the ISO |
| `pc_iop.c`, `pc_iop_tsnddrv.c` | SIF/IOP: emulated IOP memory, RPC services, Tamsoft sound driver (SPU ADPCM voices, ADSR, Sony HD/BD banks, compressed-MIDI sequences) |
| `pc_adx_rna.c`, `pc_audio.c` | CRI ADX output stage (was on the IOP) and an SDL mixer |
| `pc_movie.c`, `pc_mpeg.c` | movie player: MPEG-1 files made by `convert_movies.py`, decoded with pl_mpeg |
| `pc_mc.c` | libmc: one always-present memory card backed by the `saves` folder |
| `pc_text.c` | PC wording for the save/load messages (no memory card / slot references) |
| `pc_platform.c` | SDL window, controller and key bindings, fast-forward, input recording, logging |
| `../config/recvx_config.c` | `recvx-config.exe`, the settings app (writes `recvx.ini`; bindings in `pc/include/pc_bindings.h`) |
| `../config/setup_game.c` | game setup in the settings app: disc image -> `data`, movie conversion with a downloaded FFmpeg |
| `../res/` | icons (`pc/tools/make_icons.py`) and version information of both programs |
| `pc_system.c`, `pc_ps2_globals.c` | startup / frame code of `ps2_NaSystem.c` and `ps2_dummy.c` |
| `pc_sce_misc.c` | libpad, libvu0 helpers |
| `pc_stubs.c` | generated by `pc/tools/gen_stubs.py`: remaining unported PS2 functions |

The VU0 matrix library (`ps2_NaMatrix.c`, `ps2_NaMath.c`, `ps2_NaView.c`) is ported in place.

## Running and debugging

See the main [README](../README.md) for building, game data setup and `recvx.ini`.

`recvx.log` (next to the exe) lists stubs as they are first called; crashes and hangs (no frame
for 5 s) print a stack trace there.

Every normal run records the controller input to `last_run_input.txt` next to the exe (the
previous one is kept as `last_run_input.prev.txt`); replaying it reproduces a session exactly,
which is the easiest way to report or debug a problem.

Environment variables for testing:

| Variable | Effect |
|---|---|
| `RECVX_CONSOLE=1` | open a console window showing the log (recvx.exe has none otherwise; the log is always in `recvx.log`) |
| `RECVX_REPLAY=<file>` | replay a recorded input file |
| `RECVX_RECORD=<file>` | record input to a specific file |
| `RECVX_INPUT=<file>` | scripted button presses; `title+<n>` lines count from the title screen (format in `pc_platform.c`) |
| `RECVX_AUTOPRESS=1` | tap Start/Cross for unattended tests |
| `RECVX_SPEED=<n>` | run n times faster |
| `RECVX_SHOTS=<seconds>` | save screenshots to `shots/` periodically |
| `RECVX_GSDUMP=<frame>` | log every GS draw of that frame |
| `RECVX_DATA`, `RECVX_ISO`, `RECVX_SAVES`, `RECVX_HDTEX`, `RECVX_MOD` | override the `recvx.ini` paths |
| `RECVX_WARP=<stage>,<room>[,<entrance>[,<room case>[,<player>]]]` | a new game starts in that room instead of the first one (stage 7 room 11 is `RM_7110.RDX`; player 0 Claire, 1 Chris); the input script's presses still apply |
| `RECVX_TEST_DOOR=<area>[,<presses>]` | action press number `<presses>` in play (default 1) uses trigger area `<area>` of the current room: a door area as if walked through, any other area as if examined (for testing random doors) |
| `RECVX_SEDUMP=<file>` | write the sound effect mix as raw 16-bit stereo 48 kHz |
| `RECVX_MIXDUMP=<file>` | write the final mix as played (music, voices, effects; float32 stereo 48 kHz) |
| `RECVX_SNDLOG=1` | log sound sequence starts, rejected sequences, sequence uploads and reverb changes |
| `RECVX_MCLOG=1` | log save-folder (memory card) calls |

## Experimental GS material inspector

On the `experimental/decals-wip` branch, the numeric keypad controls a runtime material-state
inspector. It is disabled by default and does not alter game materials. The renderer's bounded
decal depth-priority heuristic runs independently of the inspector; its eligibility and behavior
are described below.

| Key | Action |
|---|---|
| `*` | Enable/disable candidate collection and magenta wireframe highlighting |
| `+` | Select the next in-frustum GS material state |
| `-` | Select the previous in-frustum GS material state |
| `/` | Mark the selected state and write its GS properties to `recvx.log` |

Candidates are unique GS material-state signatures gathered from triangle batches whose
post-projection bounds intersect the 640x480 viewport, active GS scissor and normalized depth
range. The signature includes texture, blend, alpha-test and depth registers. The selected
batch is outlined in magenta without replacing its texture or changing its original GS state.
The outline ignores depth so it remains useful for inspecting overlapping surfaces.

A marked sample logs the primitive type, texture enable/mode, ABE, TEX0 fields (TBP/TBW/PSM/TW/TH),
TEX1, CLAMP, ALPHA, TEST, ZBUF, TEXA, TEXCLUT and PABE. Samples are held in memory for the
session and written to the normal log; marking the same state twice is ignored. The inspector
records GS state signatures, not a stable game-side material pointer: different source materials
that produce identical GS state may share one candidate. The 512-candidate and 64-mark limits are
fixed diagnostic bounds.

The renderer separately applies an experimental bounded depth priority to blended, textured 3D
triangle batches using perspective UVs when Z testing is GEQUAL and ZBUF uses Z16S. Later eligible
draws receive polygon offset +1..+4 depth units (factor 0), capped at +4 and reset every frame.
This is a broad GS-state heuristic, not a semantic CNK decal identifier; ordinary transparent
geometry with the same state can also qualify. The ALPHA equation and texture PSM/TBP/size are not
eligibility checks, so conventional and additive blend equations are both covered when ABE is enabled.

The inspector itself only collects and highlights GS-state signatures; it does not apply or change
the offset. It records no source object/material identity. The numeric keypad keys above are consumed
by the platform layer and do not reach keyboard-to-pad bindings.

## Tools

```bash
python pc/tools/check.py            # syntax/type check all game sources, summary of errors
python pc/tools/check.py <files>    # check specific files; logs in build_pc/logs
python pc/tools/build.py            # build build_pc/recvx.exe (SDL2 is downloaded on first run)
python pc/tools/gen_stubs.py        # regenerate pc/src/pc_stubs.c for unresolved symbols
```

Requires Visual Studio 2022 Build Tools (MSVC x86); the path is in `pc/tools/msvc.py`.
